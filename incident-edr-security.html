Credential dumping from LSASS memory on FIN-WS-0412

A signed but unusual PowerShell chain read the memory of the Local Security Authority process and wrote it to disk, then attempted an outbound TLS session to an unclassified host. The endpoint is isolated. Credentials for the signed-in user should be treated as compromised.

This is a genuine credential-theft attempt, not a false positive. A macro-enabled invoice attachment spawned an encoded PowerShell command, which loaded comsvcs.dll and called MiniDump against PID 748 — the canonical living-off-the-land route to LSASS that avoids dropping Mimikatz on disk.

Exfiltration did not complete: the outbound session to 185.34.212.9:8443 was blocked by the network filter after 2 KB, and the endpoint was isolated 41 seconds later. The dump file C:\Windows\Temp\dbg_748.tmp was quarantined intact and is available for analysis.

Two other Finance endpoints received the same attachment from accounts@vendor-billing-desk.net at 09:02. Neither executed it, but both remain at risk until the sender is blocked at the mail gateway.
